## Feature 1: Dentist treatment plan (agent: `quote-agent`)

A dentist's treatment plan is the document an office gives after an exam: one line per recommended procedure, usually with a CDT code, tooth number, fee and a priority/phase. Example:

```
Treatment plan: Phase 1 (urgent)
  Tooth 19   Root canal, molar        D3330    $1,100
Phase 2
  Tooth 19   Crown, porcelain         D2740    $1,200
  Tooth 14   Filling, 2 surfaces      D2392    $200
  Tooth 15   Filling, 2 surfaces      D2392    $200
```

**Backend** (owns `backend/app/treatment_parser.py`, `backend/app/routers/treatment_plan.py`, `backend/tests/test_treatment_plan.py`): `POST /treatment-plan/parse` takes `TreatmentPlanParseRequest` → `TreatmentPlanParseResponse`.
- Deterministic **rules parser always runs** (works with no Ollama): detect a CDT code (`D\d{4}`) per line; otherwise match the procedure name through `app.search.search_procedures`; tooth number (`#19`, `Tooth 19`, `tooth no. 19`, ranges ignored → first number); fee (`$1,100`, `1100.00`) → `quoted_fee`; `typical_fee` = catalog `fee_p50`; `matched=True` only when a catalog code is found; `confidence` 1.0 for explicit code, 0.5–0.9 for name matches by score.
- Urgency from words/phases: "urgent", "asap", "pain", "infection", "emergency", "phase 1", "priority 1" → `urgent`; "phase 2", "priority 2", "soon", "recommended" → `soon`; "phase 3", "elective", "cosmetic", "when convenient", "monitor" → `flexible`; default `flexible`. Keep `phase` text (e.g. "Phase 2").
- Dependencies: `after` is set (to the other item's `id`) when the same tooth has a root canal (`D3330`) and a crown (`D2740`): the crown comes after the root canal. Use ids `q1`, `q2`, … in input order.
- Lines that look like treatments (have a fee or a tooth) but have no catalog match go to `unmatched_lines` (not dropped silently); headings, totals, and blank lines are ignored; add friendly `notes` (e.g. "We matched 4 of 5 lines.").
- **Optional Ollama assist**: only if `OllamaClient().is_available()` and there are unmatched lines, ask the model for JSON for those lines; **validate every returned code against the catalog and every fee against numbers actually present in the source line**; discard anything unverifiable; set `mode="ollama"` only if it contributed. Wrap in try/except so any failure silently keeps `mode="rules"`.
- Limits: empty/whitespace text → 422 with a clear detail; text over 20,000 chars → 422.
- Tests (no network/Ollama): the example above parses to 4 matched items with the right codes, teeth, fees, urgencies, and the crown `after` the root canal; fee formats; unmatched line handling; name-only lines (e.g. "crown on #30 $1,250"); empty input 422; a fake Ollama client path (monkeypatch) that proposes a bad code and a fee not in the text is rejected.

**Frontend** (owns `frontend/src/pages/TreatmentPlan.tsx`, `frontend/src/components/quote/**`, `frontend/src/pages/TreatmentPlan.test.tsx`, `frontend/src/components/quote/*.test.tsx`): replace the stub page; props stay `{ onNavigate }`.
- A textarea to paste the plan text, a **"Use a sample treatment plan"** button (fills the example above), and a **"Read my plan"** button → `postTreatmentPlanParse` (include `planRef`).
- Results as **visual cards, not a table**: per item a category-colored chip (use `CategoryChip`), CDT code, tooth badge, a **quoted vs typical price bar** (two horizontal bars from the API fields; if quoted is more than 15% above typical show an "above typical" badge), an urgency `SegmentedControl` (urgent/soon/flexible, editable), and a remove button. Show `phase` text. Unmatched lines in a clearly labeled "We couldn't read these lines" panel with the raw text; show `notes` and a small badge for `mode` ("Read with rules" / "Read with AI").
- **"Optimize my year with these"** (enabled when ≥1 matched item): build `TreatmentItem[]` from matched items (`id` = parsed id, `code`, edited `urgency`, `after`), build `quotedFees` (id → quoted_fee for items that have one), call `setDraft({ items, quotedFees })` then `onNavigate('plan-year')` (the Plan My Year page then runs the optimization automatically and shows the savings tips).
- Privacy note: "Your quote stays in this browser tab and isn't saved." No file/photo upload (mention "paste text for now"). Friendly loading/error states using `StateViews`.
- Tests: renders; sample button + read flow with a mocked fetch shows cards; editing urgency changes what is handed off; Optimize calls `setDraft` shape and navigates (wrap with the existing test helpers in `src/test/`); unmatched panel; error state.

## Feature 2: Questions to ask your dentist (agent: `questions-agent`)

**Backend** (owns `backend/app/questions.py`, `backend/app/routers/questions.py`, `backend/tests/test_questions.py`): `POST /questions` takes `QuestionsRequest` → `QuestionsResponse`. Deterministic templates, no LLM, no network.
- `safety_note` always present: "If you have pain, swelling, or an infection, don't wait on this list: call your dentist or urgent care right away."
- Sections (ids stable): `urgency` ("Is it urgent?", **always first**), `billing` ("Cost and billing"), `coverage` ("Insurance and coverage"), `alternatives` ("Other options"), `timing` ("Splitting the work over time", only when `len(codes) >= 2` or remaining annual max is low, i.e. less than 25% of the plan max, or the month is ≥ 10), plus a `procedure` section ("About <names>") with category/procedure-specific questions for the given `codes`.
- Content to cover: urgency ("Is this urgent, or can it safely wait a few weeks?", "What happens if I wait until my plan year resets?"); billing ("Which procedure codes will you bill?", "What is the full price including X-rays, numbing and temporary work?", "Is anything billed separately?", "Do you offer a payment plan or a discount for paying upfront?", "Are you in network with my plan?", "Can you send my insurer a pre-treatment estimate (predetermination) first?"); coverage (plan-aware: if the plan has a frequency limit for any given code ask about it; if `plan.alternate_benefit` ask whether my plan pays only for the less expensive option; waiting periods; "when were my last X-rays and does my plan limit how often they're covered?"); alternatives ("Is there a lower-cost option?", "Is a filling enough or do I need a crown?"); procedure-specific (crown: build-up needed? replacement frequency for the same tooth? temporary crown cost; root canal: will a crown be needed afterward and when; filling: which material and does my plan pay for it; extraction: replacement options and cost; implant/bridge/denture: what's included, healing time and stages; deep cleaning: how many quadrants, is it billed per quadrant; preventive: how often are exams/X-rays covered).
- Each `DentistQuestion` has a stable `id`, plain-English `text`, and a one-line `why`. Mentioning dollar amounts is allowed only if taken from `app.engine.status.benefits_status` (e.g. remaining max); otherwise keep questions qualitative. Unknown codes are ignored (no 404). No duplicate question ids.
- Tests: safety note and `urgency` first always; crown+filling yield procedure-specific questions; `timing` appears for 2 codes and not for 1 code early in the year with lots of max left; plan-aware frequency/alternate-benefit questions toggle with the plan (`demo_ppo` vs `basic_ppo`); unknown code ignored; ids unique; empty `codes` still returns the general sections.

**Frontend** (owns `frontend/src/components/QuestionsCard.tsx`, `frontend/src/components/questions/**`, `frontend/src/components/QuestionsCard.test.tsx`): replace the stub; props stay `{ codes: string[] }`; it reads plan/usage/month from `usePlan()` and fetches with TanStack Query (`postQuestions`; keep query keys stable; if `codes` is empty still render the general list).
- A card titled **"Questions to ask your dentist"**; the `safety_note` in a highlighted callout at the top; sections as **tappable question cards** (each a button with `role="checkbox"`/`aria-checked` that toggles "asked"), a progress bar "3 of 12 asked", a per-section progress chip, `why` shown as small helper text. **Copy list** button (clipboard, with toast/feedback) producing a plain-text checklist grouped by section; **Print** button (`window.print`). Keep ticks in component state (optionally `sessionStorage` in try/catch). No dropdowns/accordions needed; collapsible section headers are fine if done as buttons with `aria-expanded`.
- Render nothing while loading beyond a small skeleton; on error show a compact retry (use `StateViews`); never block the page.
- Tests: renders sections from a mocked response; toggling a question updates progress; copy builds the expected text (mock `navigator.clipboard`); safety note present; empty-codes behavior; error state.

## Feature 3: Savings tips (agent: `savings-agent`)

**Backend** (owns `backend/app/engine/tips.py`, `backend/app/routers/tips.py`, `backend/tests/test_tips.py`): `POST /savings-tips` takes `SavingsTipsRequest` → `SavingsTipsResponse`. **All money math lives in `engine/tips.py`** using the existing `estimate`, `run_year`, `best_schedule`, `benefits_status` (do not edit those files; call them). Every tip carries `before`, `after`, `saving = round(before - after, 2)` and `steps` (plain-English `TraceStep`s showing how it was computed) plus `assumptions`. Drop tips with `saving <= 0`. Sort by `saving` descending. With no `items` only the `preventive` tip can appear.
1. `timing`: run `best_schedule` on the items; if `savings > 0`: `before = baseline_you_pay`, `after = total_you_pay`; steps from the schedule reasons; assumption "only treatments your dentist says can safely wait are moved; urgent care stays in this plan year". If every item is urgent there is no timing tip.
2. `network`: sequentially estimate all items in network and out of network from the same starting usage; `before` = out-of-network total you pay, `after` = in-network total; saving = the balance billing avoided (+ any other difference).
3. `preventive`: from `benefits_status.unused_preventive_value`; `before` = that value (what the visits are worth), `after` = 0 (what the plan makes them cost you); only when value > 0; summary says "free covered care".
4. `alternative`: for each item whose catalog `alternative_codes` has an entry in the catalog: `after` = you-pay for the alternative (in network); `before` = you-pay for the chosen procedure; if `plan.alternate_benefit` is true the plan only pays what it would pay for the alternative (plan_pays from the alternative's estimate), so `before = billed(chosen) - plan_pays(alternative)`; otherwise `before` = normal estimate you-pay. Assumption: "only if your dentist agrees the less expensive option is right for the tooth". One tip per item, title names both procedures.
5. `fsa_hsa`: `before` = total in-network you pay for the items (sequential from the usage); `after = before * (1 - tax_rate)`; steps show the rate; assumptions: "uses an assumed tax rate of X% (adjust it); rules and deadlines for your FSA/HSA vary; this is not tax advice". Only when `before > 0`.
6. `quote_check`: for each item id in `quoted_fees`: if `quoted > catalog fee_p80` then `before = quoted`, `after = fee_p80`; summary: your quote is above the typical range; ask the office to explain; potential, not guaranteed. Skip otherwise.
- Unknown item codes: 422 with a clear detail. `items` limited to 10 (422 beyond that).
- Tests: with the S2 items on `demo_ppo` (`max_used=1100`, `deductible_met=50`, month 11) the `timing` tip has `before=2300`, `after=1405`, `saving=895`; a single crown fresh-year `network` tip saving 300 (billed 1500 vs 1200: you pay 925 vs 625); `alternative` for D2392 on `demo_ppo` (alternate benefit) vs `basic_ppo`; `fsa_hsa` math at two tax rates; `quote_check` triggers at 1,600 for a crown (p80 1,500) and not at 1,400; preventive tip from usage with one cleaning done; sorted descending; no tip has `saving <= 0`; 422 cases; golden numbers untouched.

**Frontend** (owns `frontend/src/components/SavingsTips.tsx`, `frontend/src/components/savings/**`, `frontend/src/components/SavingsTips.test.tsx`): replace the stub; props stay `{ items: TreatmentItem[]; quotedFees?: Record<string, number> }`; reads plan/usage/month from `usePlan()`; TanStack Query with a stable key including items, quotedFees and tax rate.
- Card titled **"Ways to save"** with the response `note` (tips overlap, never sum them). Each tip is a **visual card**: icon by `kind` (lucide), title, plain summary, a large saving amount, and a **before → after mini bar visual** drawn from `before`/`after` (Recharts or simple proportional bars); tap the card (button with `aria-expanded`) to reveal "How we calculated this" (the `steps`) and the `assumptions`.
- For the `fsa_hsa` tip, show a **tax-rate slider** (`SliderField`, 10–40%) that refetches with `tax_rate` (debounce lightly); the rate is an input, the saving still comes from the API.
- Render nothing when there are no tips and nothing is loading; skeleton while loading; compact retry on error; never block the page.
- Tests: renders tips from a mocked response; expanding shows steps/assumptions; the before/after values come from the API (e.g. "$2,300" and "$1,405" with saving "$895"); slider triggers a refetch with `tax_rate`; empty state; error state.
