## Must fix before the demo

1. **The demo's first step does not work.** `frontend/src/pages/Login/LoginPage.tsx:226` redirects to `/` whenever the session is already "ready", and `frontend/src/state/SessionContext.tsx:119-127` signs in as Jordan automatically on load. So opening `/login` (DEMO.md step 1) bounces to Home and the audience never sees a sign-in screen. The page is also still the plain placeholder ("Simple on purpose", T17 is Ulisses's). To see it you must find the sign-out control first (`signOut` sets "signed-out", Shell then redirects to `/login`). Fix: decide the demo opening. Either (a) show `/login` first by not auto-signing in when no member is remembered in `sessionStorage`, or (b) rewrite DEMO.md step 1 to "open Home, sign out, pick Jordan". Confirm the sign-out button exists in the UtilityBar and is easy to find. Make sure the login cards use the Sai look (D5).
2. **Frontend adds dollar amounts (breaks hard rule 1).** `frontend/src/features/home/useHome.ts:83`: `deductible_met: base.deductible_met + est.deductible_applied`. This is the only real money arithmetic I found in the frontend (other math is percentages for progress bars). It also feeds `postBenefits` for the "benefits left" numbers after "Log a visit". Fix: return the updated usage from the backend (add a `usage_after` field to the estimate result, or a small `POST /members/{id}/visits` that uses `Store.record_visit`, which already exists in `store.py:132` but has no route), and display it. Add a test that no money addition happens in the client.
3. **"Log a visit" looks real but is not saved.** `frontend/src/pages/Home/HomePage.tsx:164-200` and `useHome.ts:61-97`. The result lives only in React state: it resets on page change or refresh, and Plan My Year, Costs and the Assistant keep using the database usage. The card does say "only changes the numbers ... on this page", but the title "Log a visit" promises a record, and a demo viewer will assume the $400 left changes everywhere (FEATURES.md F1 acceptance: "everywhere in the app"). Fix: either rename it "Try a visit" and keep the note, or persist it through a real endpoint (same as item 2) and reload the overview. Pick one before the demo; renaming is a 2 minute fix.
4. **Fresh clone starts with an empty database.** `backend/app/routers/session.py:23-27` creates `Store()`, whose `migrate()` creates `database/benefits.db` empty. `backend/app/db/__main__.py:21` then only seeds when the file does not exist, so `python -m app.db` (without `--reset`) after the first backend start leaves zero accounts, and the app shows "No demo accounts are available." DEMO.md's checklist uses `--reset`, which is right, but it is a one-step trap on the demo machine. Fix: in `Store.__init__` (owner: database agent) seed when the `households` table is empty, or have `/auth/demo-accounts` fail with a clear "run python -m app.db --reset" message. Add the command to the `scripts/` start script.
5. **DEMO.md, README, SETUP and TASKS are stale and would mislead the presenter.** `docs/DEMO.md:6-23, 63` marks Login, Plan My Year, Assistant, Costs as "NOT BUILT"; they are built. Test counts are wrong everywhere (`README.md:61` and `docs/SETUP.md:20` say 148; `DEMO.md:63` says 148 and 10; actual 199 and 48). `docs/TASKS.md:6-30` still lists T05 to T12 as "not started". Fix: docs agent rerun (T15), then re-verify each DEMO step in a browser, including step 6 ("Jordan has $210 of $1,500 used": confirmed in seed).

## Should fix

6. **Assistant side panel is not a proper dialog.** `frontend/src/components/shell/AssistantButton.tsx:30-37`: `role="dialog"` with no `aria-modal`, no Escape key, no focus move into the panel and no focus return to the button; the backdrop is a clickable `<div>`. Fix: move focus to the panel on open, close on Escape, return focus on close (the old `components/ui/sheet.tsx` or `dialog.tsx` from shadcn already does this and is unused).
7. **Items from a pasted dentist quote default to "flexible", so the scheduler may move them to next year.** `backend/app/treatment_parser.py:50-66` returns `None` when no urgency word is found, and the model default is `flexible` (`backend/app/models.py:101`). The Plan My Year builder also adds every new treatment as flexible (`frontend/src/features/planYear/usePlanYear.ts:108`). Savings come from moving care, so an item the patient never classified can be told to wait. The page does say "Urgent or painful care should never wait" (`PlanYearPage.tsx:65`), which is good, but the safer default is "soon" for unmarked items, plus a visible nudge ("Mark anything painful as Urgent") above the timeline. Also, "soon" items can still move to January in `engine/sequencer.py:114` (only "urgent" is pinned); the hint text for "Soon" ("next few months") should say whether it can move. Fix: default to "soon" and decide the rule for "soon" with M.
8. **The assistant's safety wording is only in the prompt.** `backend/app/agent/loop.py:28-47` rule 4 (pain and swelling) and rule 5 (disclaimer) are not checked in code, and no test covers them (grep for "pain", "urgent", "swelling" in `backend/tests/test_agent_assistant.py` and `test_chat.py` finds nothing). The number guard is tested; the safety rule is not. Fix: add a fake-provider test that a pain message gets the "contact your dentist right away" reply path, or add a small code-side check (the chat panel does show the static `Disclaimer`, `AssistantChat.tsx:221`, which covers the disclaimer).
9. **Number guard is weaker than it sounds.** `backend/app/agent/guard.py:12-35`: it only checks `$` amounts, accepts any value within $1 of *any* number in any tool result (including ages, scores, months), and misses "800 dollars", "$1.2k" or amounts written in words. The retry plus template fallback is good. Fix: also match `N dollars`; only allow numbers from money-named fields. Low effort, and DEMO line 8 ("The AI only explains it") depends on it.
10. **Unauthenticated, unbounded stateless chat.** `backend/app/routers/chat.py:116-120`: `POST /chat` without `member_id` needs no token, and `ChatRequest` (`models.py:181`) has no limit on message count or length, so anyone who can reach the server can spend the Anthropic key. Same for `/estimate`, `/schedule`, `/savings-tips` (cheap, no model). Fine on localhost; do not deploy as is. Fix: `max_length` on messages and content; require a token for chat even without `member_id`. Also `_ATTACHMENTS` (`chat.py:54`) is an unbounded in-memory dict; cap the count.
11. **Demo login is open and tokens never expire.** `routers/auth.py:19-26` signs anyone in as any member by id; `routers/session.py:36-51` tokens are HMAC of the member id with no expiry. That is the decided demo level (F1) but the CORS list and the `/docs` page make it look like a real service. Add one line to `docs/ARCHITECTURE.md` and the README: "Demo only; do not expose to a network." Set `SESSION_SECRET` in `.env.example` so tokens survive a `--reload` restart (right now every restart signs everyone out, and the app then shows an error instead of the login page; `SessionContext.tsx` only re-signs in on page load).
14. **"Send invite" button sends nothing.** `frontend/src/features/family/MemberDetail.tsx:86-88` is labelled "Send invite" and says "Sending…"; after success it says "no email is sent" (good, honest). Rename the button to "Create invite" so the label matches.
12. **No end-to-end test.** `tests/e2e/` is empty and Playwright is not in `package.json`; FRONTEND/CONVENTIONS call for one for each acceptance line. The frontend page tests mock the API and assert the mocked numbers (for example `PlanYearPage.test.tsx:53`), so they prove rendering, not that backend and UI agree. The new contract tests (`backend/tests/test_contract_*.py`) cover the backend side; add one browser run of the S2 path if time allows (see "What to cut").
13. **Landing page and style guide are leftovers from the old theme.** `/welcome` (`pages/Landing.tsx`, `components/landing/*`) uses the editorial look, not Sai's (D5), and hard-codes golden figures (`Hero.tsx:239-260`, `SavingsMoment.tsx:8-9`: $40, $175, $800, $625; I checked they match G3/G4 and a filling at 80%). They are marketing copy but are not labelled "example". `/style` (`StyleGuide.tsx`) is routed in the live app with hard-coded $800 / $895 (`App.tsx:296`). Fix: label the landing numbers "Example", and remove `/style` and `/welcome` from the demo build or leave unlinked (neither is linked from the shell today).

## Demo risks and what to cut
- **Highest risk:** the assistant. It needs the key in `backend/.env` and internet; if Anthropic is slow, one answer can take several tool round trips (max 5 steps, 60 s timeout, `providers.py`). Keep the fallback in DEMO.md ready (`/docs` -> `POST /schedule`) and rehearse the exact two questions. Check `/health` shows `chat_mode: anthropic` before going on stage.
- **Second:** server restart or `--reload` during the demo invalidates every token (random `_SECRET`) and the SPA shows an error until a full page reload. Start the backend without `--reload` on stage, and set `SESSION_SECRET`.
- **Third:** the first step (item 1) and the seeded database (item 4).
- **Cut first if time runs out:** Plans comparison polish, the annual calculator (`YearlyView`), the quote reader, the questions checklist, `/welcome`. **Never cut:** sign-in per member (D13.1), Plan My Year S2 ($2,300 / $1,405 / $895), the per-person assistant, the disclaimers.
- A 60 second Playwright run of the S2 path, or a recorded video, would be a better use of the last hour than new features (DEMO.md says the backup recording is not done).
