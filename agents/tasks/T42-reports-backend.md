2. Also for Marc one open EOB (you owe more than $0) so the "what do I owe right now" total is not zero. Use fictional claim and EOB numbers and the provider names from `providers.json` where they fit.
3. Routes (new `backend/app/routers/reports.py`, one `include_router` line in `main.py`, models appended to `models.py`) exactly as the contract: `GET /reports/samples`, `POST /members/{id}/reports/samples/{sample_id}`, `POST /members/{id}/reports/upload`, `GET /members/{id}/reports` with `totals` computed in code from stored values, `GET .../{id}`, `GET .../{id}/explain`, `POST .../mark-paid`, `DELETE`. Same visibility rules as saved plans (primary any member, adult only themself, managed denied). Demo family only for writes. Max 100 items per member. Sample documents: a paid claim, an EOB with a deductible, an out-of-network EOB with balance billing, a denied claim, a copay-style visit, in a clearly synthetic text template beginning with the line `MOLAR MONEY SAMPLE DOCUMENT`. The parser accepts only that template (422 "Demo accepts the sample documents only."). Parsing is code, never the model; reject angle brackets and over-long values; never echo raw uploaded text into prompts.
4. The explain endpoint is deterministic code (no model): what the document is, each line in plain words, ordered steps billed, allowed, deductible, plan paid, you owe, what to do next, and a balance billing note for out of network. Plain language, 8th grade level, estimate/synthetic disclaimer, never advise delaying urgent care. Amounts are the stored values; the only arithmetic allowed is summing stored values for totals and a check that stored lines add up (put any such helper in `backend/app/engine/` per the money rule).
5. Notifications: add generation of `claim_update` (a claim with status denied or pending) and `eob_ready` (an EOB with you_owe above 0 and unpaid) in `backend/app/notifications.py`; dedupe keys per item; the kinds already exist in the table.
